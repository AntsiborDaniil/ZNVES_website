# Стратегии раздачи HTML по страницам

Рекомендации по лучшим технологиям раздачи для каждой страницы проекта.

---

## Сводная таблица

| Страница | Сейчас | Рекомендация | Зачем |
|----------|--------|--------------|--------|
| `/` (главная) | Статический shell, данные с клиента | **SSG** или **SSR/ISR** для блоков товаров | SEO, быстрый первый экран (NEW IN / CATALOG) |
| `/catalog` | Статический shell, данные с клиента | **SSG** или **ISR** | SEO каталога, меньше мерцания загрузки |
| `/new-in` | Аналогично каталогу | **SSG** или **ISR** | То же |
| `/catalog/[slug]` | SSG по slug, данные товара с клиента | **SSG с данными** или **ISR** | SEO карточки товара, мгновенный контент |
| `/cart` | Клиентская страница | **Статический shell + гидратация** | Корзина всегда персональная, контент из localStorage |
| `/checkout` | Клиентская страница | **Статический shell + гидратация** | Форма и корзина на клиенте |
| `/login` | `force-dynamic` | **SSR (force-dynamic)** ✓ | Не кешировать форму входа |
| `/register` | `force-dynamic` | **SSR (force-dynamic)** ✓ | Не кешировать форму регистрации |
| `/account` | Клиентская, без dynamic | **SSR (force-dynamic)** | Не отдавать кешированный HTML личного кабинета |
| `/privacy` | Статика | **SSG** ✓ | Текст не меняется, идеально для статики |
| `/public-offer` | Статика | **SSG** ✓ | То же |
| `/placeholder` | Статика | **SSG** ✓ | Заглушка, статика |

## Детали по страницам

### 1. Главная (`/`)

- **Сейчас:** Серверный компонент отдаёт разметку, блоки NEW IN и CATALOG грузят товары в `ProductDisplaySection` на клиенте (useEffect + fetch).
- **Лучше:** Загружать списки товаров на сервере и отдавать их в первом HTML (SSR или SSG с revalidate). Так первый экран быстрее и контент виден поисковикам без JS.
- **Варианты:**
  - **SSR:** в `page.tsx` (async) вызвать `fetchNewInProducts()` и `fetchAllCatalogProducts()` (или аналог), передать в секции как props — каждый запрос получит свежий HTML.
  - **ISR:** то же, но с `revalidate: 60` (или 300) в fetch — кеш с обновлением раз в N секунд.

---

### 2. Каталог (`/catalog`) и New In (`/new-in`)

- **Сейчас:** Страница без "use client", но контент в `CatalogPageContent` — клиентский, товары и фильтры подгружаются после гидратации.
- **Лучше:** Первую выдачу (например, без фильтров или с дефолтной категорией) отдавать с сервера.
- **Варианты:**
  - **SSR:** в `page.tsx` запросить товары по умолчанию, передать в клиентский компонент как initial data.
  - **ISR:** то же + `revalidate` в fetch — меньше нагрузка на API, контент всё равно периодически обновляется.

---

### 3. Карточка товара (`/catalog/[slug]`)

- **Сейчас:** `generateStaticParams` строит список slug’ов при сборке; сама страница только передаёт `slug` в `ProductPageClient`, который в useEffect запрашивает товар с API. То есть HTML страницы пустой/скелетон до загрузки с клиента.
- **Лучше:** Данные товара получать на сервере и отдавать в первом HTML.
- **Варианты:**
  - **SSG с данными:** в async `ProductPage` вызывать `fetchProductWithWarehouse(slug)` и передавать результат в клиент как props. В `generateStaticParams` оставить текущую логику (или fallback: []). Тогда при сборке все известные slug’и получат готовый HTML.
  - **ISR:** в серверном компоненте `fetch(..., { next: { revalidate: 300 } })` — те же данные с сервера, но с периодическим обновлением кеша.
  - Для новых slug’ов, которых не было в `generateStaticParams`, Next при первом заходе сделает on-demand генерацию (если не отключено), и после этого можно кешировать (ISR).

---

### 4. Корзина (`/cart`) и Оформление заказа (`/checkout`)

- **Сейчас:** Полностью клиентские страницы: контент зависит от корзины (context/localStorage) и форм.
- **Рекомендация:** Оставить **статический shell + гидратация**. Не нужны ни SSG с персональными данными, ни обязательный SSR: первый HTML может быть оболочкой (шапка, футер, контейнер), содержимое заполняется на клиенте. Так и должно быть для корзины и чекаута.
- При желании можно добавить `export const dynamic = "force-dynamic"`, чтобы сам HTML страницы не кешировался CDN (опционально, не обязательно).

---

### 5. Логин (`/login`) и Регистрация (`/register`)

- **Сейчас:** `export const dynamic = "force-dynamic"` — страницы не кешируются.
- **Рекомендация:** Оставить **SSR (force-dynamic)**. Формы входа/регистрации не должны отдаваться из кеша (из соображений актуальности и безопасности). Всё ок.

---

### 6. Личный кабинет (`/account`)

- **Сейчас:** "use client", проверка авторизации и данные только на клиенте, без `dynamic`.
- **Рекомендация:** Добавить **`export const dynamic = "force-dynamic"`** в `account/page.tsx`. Так Next не будет отдавать закешированный HTML страницы аккаунта (например, с прошлого пользователя). Сама логика (редирект в бота, заказы и т.д.) остаётся клиентской.

---

### 7. Юридические страницы (`/privacy`, `/public-offer`) и заглушка (`/placeholder`)

- **Сейчас:** Статический контент, без клиентского фетча.
- **Рекомендация:** Оставить **SSG**. Контент не персональный и редко меняется — статика даёт максимальную скорость и минимум нагрузки на сервер.

---

## Итог

- **Оставить как есть (и так оптимально):** `/login`, `/register`, `/privacy`, `/public-offer`, `/placeholder`; корзина и чекаут — статический shell + клиент.
- **Имеет смысл доработать:** главная, каталог, new-in — отдавать первый список товаров с сервера (SSR или ISR); карточка товара — получать данные в серверном компоненте (SSG/ISR с данными).
- **Небольшое улучшение:** добавить `force-dynamic` для `/account`.

Если нужно, могу предложить конкретные правки в коде (например, серверный fetch для главной или для `/catalog/[slug]`).
